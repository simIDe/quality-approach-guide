# Example: weekly training load

A minimal, end-to-end *data product* (data prepared for one specific user and one specific decision).

- **For whom:** the coach of a running club.
- **What they get:** a Markdown report with one row per athlete per week over eight weeks, and the load of each week (perceived exertion from 0 to 10 × duration in minutes).
- **The data:** synthetic, generated by a script with a fixed seed. The athletes (A01 to A06) are fictional. No personal data.

The generator deliberately introduces four defects. The checks detect them and the report says how each one is handled.

| Defect introduced | Dimension that detects it | Handling |
| --- | --- | --- |
| Three durations entered in hours instead of minutes | consistency | corrected (duration × 60) |
| A week with no session for athlete A03 | completeness | flagged (nothing is made up) |
| A session entered twice | uniqueness | excluded (a single copy kept) |
| A perceived exertion of 14 on a 0 to 10 scale | accuracy | excluded (the true value is unknown) |

The fifth check, timeliness, verifies that the latest session is less than seven days before the end date of the data. It passes.

## Run the example

You need Python 3.11 or later and [uv](https://docs.astral.sh/uv/). From the repository root:

```bash
uv run python examples/training-load/run.py
```

This command sets up the environment if needed, generates `data/sessions.csv`, loads it into SQLite, runs the checks, computes the weekly table and writes `output/report.md`. The database `output/training_load.sqlite` stays available to explore the tables. The `data/` and `output/` folders are recreated on every run and are not versioned.

## Run the tests

```bash
uv run pytest -q
```

## Without uv: pip and venv

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install pytest
python examples/training-load/run.py
python -m pytest -q
```

The example uses only the Python standard library; pytest is only used for the tests. With pip, the pytest version is not pinned the way `uv.lock` pins it.

## What is in this folder

| File | Role |
| --- | --- |
| `run.py` | single entry point: chains the steps and writes the report |
| `generate.py` | generates the synthetic CSV and its four defects |
| `pipeline.py` | loads the CSV into SQLite, cleans it, computes the load in SQL |
| `checks.py` | one quality check per dimension |
| `tests/test_example.py` | tests of the transformation and the checks |
| `product-sheet.md` | for whom, for which decision, what is guaranteed or not |
| `data-dictionary.md` | every column of every table |
| `method-log.md` | excerpt of the log: decisions, use of AI |

This is an example, not a template to copy.
