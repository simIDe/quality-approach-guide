## Use of AI

- **What was asked:** a coding agent was asked to write the example from the repository spec: tests first, a single command, under 300 lines of Python, names in French. It was later asked to translate the example to English with the same behaviour.
- **What was kept:** the split into four files (generate, load and transform, check, run), the SQL of the weekly table, the tests.
- **What was rejected or corrected, and why:**
  - the first version was over 300 lines (313): it was tightened, without removing any check or test;
  - the first version kept the SQLite database in memory: it is now written to `output/training_load.sqlite`, so that a student can open the tables and rerun the queries.
- **What was never sent to the agent:** no real data, no secret. There are none in this project.

## What we would do differently

- Detect duplicates on the (athlete, date) key in the cleaning step too, not only strictly identical rows: two different entries for the same day would pass the cleaning today, even though the uniqueness check flags them.
- Show the missing week as an empty row of the table rather than by its absence, so that the coach sees it without reading the anomalies section.
- Ask the source to enter the duration in a single unit, rather than correcting it afterwards with a threshold.
